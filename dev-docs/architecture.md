# Initial architecture boundaries

Status: bootstrap, 2026-10-14; `:session` added 2026-10-15 (WI-05); persistence and recovery added 2026-10-15 (WI-06); offline AI and hints added 2026-10-15 (WI-07); app logic layer added 2026-10-15 (WI-08a); rooms, lobby, LAN and watchers added 2026-10-15 (WI-09); Bluetooth adapter and permission gate added 2026-10-15 (WI-10); release gate, diagnostics export and release records added 2026-10-15 (WI-12). Modules implemented: `:app`, `:core`, `:session`.

`:app` owns Android lifecycle, native Compose presentation, accessibility semantics and design-token usage. It must not become the authority for legal moves, another seat's private data, observer grants or network-driven mutation. Since WI-08a it depends on `:core` and `:session` (never the reverse) and holds a plain-JVM logic layer: `cn.wpgd.app.owner.SessionOwner` (application-scoped; solo play hosts an in-process `SessionHost` with three AI seats and joins it as a `SessionClient` over the in-memory transport, all session work on one loop thread, AI decisions on a worker thread), `cn.wpgd.app.table` (`TableViewModel`, `TableUiState` derived only from the member's own projection, card selection, layout A, wildcard preview, effects keyed to event ids, wake policy, result explanation) and `cn.wpgd.app.data` (preferences, nickname, history and identity, each in its own store). The end-to-end driver reads codes through `AutomationHook`, implemented only in the `debug` source set (`dev-docs/automation-hook.md`). The Android framework appears only in `WpgdApplication`, `SharedPreferencesKeyValueStore`, (WI-09) `lan.NsdRoomDirectory` and (WI-10) `ble.AndroidBleRadio` and `ble.AndroidBleEnvironment`.

Since WI-09 the same owner also hosts or joins rooms. `cn.wpgd.app.room` holds the plain-JVM room logic: `RoomNetwork` (listen, connect, announce, browse), adverts with strict TXT decoding and a 4-digit table code, the room finder, room settings, saved tables (restore, explicit delete), and pure screen models (`RoomScreen`, `LobbyUi` using the session's `LobbyGate`, `PlayOrWatch`, `WatchUi`, `RulesSheet`). `cn.wpgd.app.lan` is the LAN adapter: `SocketTransport` carries the session's chunks as u16-length records over TCP (bounded record size and send window, graceful close that still delivers what was accepted, every callback handed to the session loop) and `LanServer` bounds accepted connections. A room is found by Android NSD discovery or by its address (join by address, `room.AddressJoin`): where discovery cannot reach the host (phone hotspots, guest Wi-Fi that isolates phones, emulators), the joiner types the host's address and port, shown in the host's lobby (`lan.HostAddresses`: its Wi-Fi or hotspot interfaces only). One plain `room_query` is answered with a `room_listing` carrying exactly the advert's public facts, and the host closes (`session.client.RoomLookup`); joining is then a new connection through the unchanged hello, six-digit code comparison, approval and host-key pinning (G2). The listing's host key is unauthenticated, like an advert's: a first join is protected by the code, a rejoin by the pinned key (`AddressJoinOverLanTest`). Rooms add nothing to the protocol's authority: admission, seats, ready, start, grants and recovery stay in `SessionHost`; the app only asks. A joined member whose host is lost keeps rejoining with its capability, and meanwhile watches discovery for its room id, because a restarted host listens on a new port or Bluetooth address; the seat still follows the capability, never a name or an address (GDN-085, `HostPortChangeRejoinTest`). The kill switches `Features.SPECTATORS` (no watching, no private follow) and `Features.TRIBUTE_PROFILE` (no new table; saved tables and joined rooms keep their frozen profile) are build constants in `room/RoomUi.kt`. A solo owner is built without the room network and storage (`SoloNeedsNoNetworkTest`), so solo play stays offline and permission-free; rooms need only INTERNET (`app/permissions-allowlist.txt`, checked by `ManifestPermissionsTest` and `tools/ci.sh`). Hosted tables are saved under app-private files, excluded from backup.

Since WI-10 the same room layer runs over Bluetooth LE. A `RoomNetwork` has one medium (`RoomMedium.LAN` or `BLUETOOTH`) and reaches only endpoints of that medium (`LanEndpoint`, `ble.BleEndpoint`); the app never switches medium by itself, and `RoomInfo.medium` names the one in use. `cn.wpgd.app.ble` keeps plain Kotlin apart from the Android glue: `BlePacketCodec`/`BleReassembler` split each session chunk at the link's ATT payload and reassemble it with bounded memory (never a partial or spliced record), `BleLink` is the session `Transport` over one GATT connection (one packet in flight, window, linger, metrics), `BleRoomNetwork` and `BleRoomBrowser` serve and find rooms through a `BleRadio` interface (GATT service with a readable advert, a write characteristic towards the host and a notify characteristic towards each joiner; the advertisement carries only the service UUID), and `BleGate` decides the permission screens. `AndroidBleRadio` implements `BleRadio` with platform `android.bluetooth` only (no Google Play services); JVM tests use a fake radio. The `bleTransport` flag is a Gradle property (`wpgd.bleTransport`, default off): off, there is no Bluetooth entry and the manifest declares no Bluetooth permission; on, `app/src/bleTransport/AndroidManifest.xml` adds the three Android 12+ runtime permissions, and Bluetooth is built only when a user opens a Bluetooth room after the gate, so solo play and Wi-Fi rooms never need a Bluetooth permission (`BluetoothEntryTest`). Bluetooth rooms are offered on Android 12+ only, because older versions require a location permission to scan.

`:core` contains immutable card identities and fixture data, the rule profile, classifier and legal-action generator (`core.rules`, WI-02), and the deal reducer (`core.state`, WI-03): a deterministic `(state, command) -> (state', events) | rejection` function with an injected PRNG (SplitMix64), typed events with a visibility class, an in-memory event log with replay, a host-internal state hash, and member, spectator and AI projections built by one code path. `core.ai` (WI-07) holds the offline AI: a policy receives only a `PolicyInput` (the seat's own projection plus its own legal options, checked to name only its own cards), runs under a deterministic step budget with a cancellation flag and a seeded tie-break source, and always yields one legal action (its answer, its best answer so far, or a deterministic fallback); per-seat settings change only at deal boundaries; hints use the same inputs and policy. It contains no Android imports, transport code, UI state, device IDs, Java UUID dependencies or inherited upstream game implementation; `CoreMultiplatformGuardTest` fails the build on any `java.*`, `javax.*` or `android.*` use in `core/src/main`.

`:session` (WI-05, `session/README.md`) is a plain JVM module that depends on `:core` only; `:core` never depends on it, and `SessionArchitectureGuardTest` fails on any Android or Compose use in `session/src/main`. It holds the transport-independent protocol: chunk framing with bounded reassembly, sealed frames, strict JSON wire messages, admission, idempotent commands with keyed-digest receipts, per-member projections, observer grants, heartbeats, and a seeded in-memory transport with fault injection. Its host authentication follows the owner-delegated G2 default (since wire protocol 2, now 3, which adds why a grant ended: per-room static host key in the key agreement, pinned fingerprint, rejoin by HMAC proof instead of the capability; `dev-docs/decisions/G2-host-authentication.md`, no external cryptography review); its grant policy is the proposed G4 default, which the project owner deferred (devices later). Since WI-06 it also owns persistence (`session.storage`: an append-only event log with commit markers and a high-water mark, checkpoints as a replay cache, recovery, retention) behind a small `Storage` interface, and the one recovery transition for disconnect, grace, pause and substitution (`host/Recovery.kt`). Since WI-07 `session.ai` drives AI seats inside the host's (epoch, turn revision, controller) binding with a scheduler deadline, and computes hints on the requesting member's device only. `:core` owns the persisted form of its own typed events and state (`core.match.MatchEventCodec`, `MatchStateCodec`) because only it can rebuild those types.

Since WI-12 the release path has three guards. `cn.wpgd.app.release.ReleaseGate` runs first in `WpgdApplication.onCreate` and stops a release build (`BuildConfig.RELEASE_GATE`, set only by the `release` build type) that carries a provisional rule profile; Gradle's `verifyReleaseDistributable` refuses to sign such a release, one whose profiles have no `**Status: SIGNED**` record in `dev-docs/decisions/` naming each profile's id, version and canonical hash, or one without a recorded project license (MIT since 2026-10-16). Local diagnostics are an allow-list in `:session` (`session.diagnostics`: every line is a `DiagnosticField` whose value is a count, revision, flag, fixed enum token or a rule profile's public id/version/hash, so no free text can enter); `:app` adds its owner counters and a crash count (`diagnostics.CrashCounter`) and shows the text in settings on request. Nothing is sent. `release/` holds the capability catalog and the license inventory that tests hold against the code and the resolved release classpath. The `r8check` build type shrinks like `release` but is debug-signed and ungated, so serialization can be checked on a device under R8.

Session boundaries (implemented by WI-05 and WI-06; G2 as the owner-delegated default, G4 deferred by the project owner): one host authority per session epoch; commands and receipts tied to turn/revision/capability; per-member private projections; ordered bounded framing; atomic versioned checkpoints; seat-private AI observation. BLE and local Wi-Fi are adapters above the same contract. Spectators are independent read-only members, not extra playing seats. Nearby sessions have no mandatory cloud account or Google Play services dependency.

An iPhone client is planned but no SwiftUI/KMP choice is finalized by this bootstrap. The shared-core option and native-client parity must be proven with common fixtures; HTML exports are not embedded as the mobile product.

The files in `dev-docs/reference/` are historical audit/target documents from 2026-10-13. Their proposed work items and commands are not current implementation status. Some reference paths describe the earlier local research environment. Use this document and README for the actual module/build structure, and `dev-docs/implementation-plan.md` for work-item status.
